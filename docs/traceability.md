# Requirements-to-tests traceability

| Requirement | Verification ID | Method |
|---|---|---|
| REQ-01 | TEST-CTRL-01 | Inspect repository controls: clean-room declaration, no submodule, no symlink, no absolute local path in project text files. |
| REQ-02 | TEST-SYN-01 | Parse the committed synthetic PDF and verify the normalized model. |
| REQ-03 | TEST-SYN-02 | Execute twice and compare normalized JSON, report, and manifest bytes and hashes. |
| REQ-04 | TEST-SYN-03, TEST-SYN-04, TEST-SYN-05 | Verify missing field, duplicate code, and malformed numeric value fail closed without a report. |
| REQ-05 | TEST-SYN-01, TEST-SYN-03, TEST-SYN-04, TEST-SYN-05 | Verify success/failure manifests and SHA-256 evidence. |
| REQ-06 | TEST-SYN-01 through TEST-SYN-05 | Execute the five defined synthetic cases. |
| REQ-07 | TEST-CTRL-02 | Verify every requirement ID has a traceability mapping and every verification ID is identified. |
| REQ-08 | TEST-CTRL-03 | Verify required public documentation exists and carries the synthetic/non-production boundary. |
| REQ-09 | TEST-CTRL-04 | Execute the documented command-line workflow in a temporary directory. |
| REQ-10 | TEST-CTRL-01, REVIEW-01 | Automated boundary scan plus Human Owner review before any remote, push, publication, or release action. |

## Synthetic verification cases

| ID | Case | Expected result |
|---|---|---|
| TEST-SYN-01 | Valid synthetic report | Success; normalized JSON, report PDF, and success manifest are produced. |
| TEST-SYN-02 | Same valid input executed twice | Generated bytes and SHA-256 values are identical. |
| TEST-SYN-03 | `SUBJECT_ID` omitted | `MISSING_FIELD`; failure manifest; no report. |
| TEST-SYN-04 | Duplicate result code | `DUPLICATE_RESULT`; failure manifest; no report. |
| TEST-SYN-05 | Non-numeric result value | `INVALID_NUMBER`; failure manifest; no report. |

## Review gate

`REVIEW-01` remains a Human Owner action. Automated checks cannot prove intellectual-property provenance or authorize publication.
